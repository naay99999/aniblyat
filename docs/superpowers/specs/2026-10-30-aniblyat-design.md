# aniblyat — เอกสารออกแบบ (feature + stack)

วันที่: 2026-10-30
สถานะ: รอผู้ใช้อนุมัติ

## เจตนาและเหตุผล

เว็บดูข้อมูลอนิเมะส่วนตัว ใช้คนเดียวเป็นหลัก เปิดมาแล้วรู้ทันทีว่า "ซีซันนี้มีอะไรฉาย ตอนต่อไปมาเมื่อไหร่ อีกกี่วัน" กดดูรายละเอียดได้ และเก็บเรื่องที่ติดตามไว้ในลิสต์ แรงบันดาลใจด้านโครงหน้าคือ anichart.net (หน้าแรกเป็น section, มีหน้า season ให้เลือกดู) แต่ไม่ใช่การลอกเว็บนั้น

เน้น **แสดงข้อมูล เข้าดูง่าย** — เรื่องดีไซน์ภาพ (สี, ฟอนต์, สไตล์) ทำทีหลัง ในเฟสนี้ทำให้ใช้งานได้ครบ อ่านง่าย และ responsive บนมือถือพอ

## Goals

- ดูอนิเมะของซีซันใดก็ได้ (ปัจจุบัน, ย้อนหลัง, ซีซันหน้า)
- ทุกเรื่องที่กำลังฉาย บอก "ตอนถัดไป EP x · อีก N วัน" พร้อมวัน/เวลาฉายจริง
- หน้าแรกที่สรุปภาพรวมเป็น section
- บันทึกเรื่องลงลิสต์ส่วนตัว และดูลิสต์พร้อม countdown
- ได้ลองเฟรมเวิร์กที่ไม่ใช่ React/Next.js

## Non-goals

- ไม่มีระบบล็อกอิน ไม่ sync กับบัญชี AniList ไม่ sync ข้ามเครื่อง
- ไม่มีลิงก์ไปเว็บดูอนิเมะ/สตรีมมิ่ง
- ไม่ทำดีไซน์ภาพแบบจริงจังในเฟสนี้
- ไม่มีสถานะในลิสต์ (กำลังดู/ดูจบ/ดองไว้) — ลิสต์เดียว
- ไม่มี backend ของตัวเอง

## Anti-goals (ถ้าเป็นแบบนี้ถือว่าพลาด แม้จะ "ทำงานได้")

- countdown ค้างหรือผิด: เปิดแท็บทิ้งไว้แล้วตอนที่ฉายไปแล้วยังโชว์ "อีก 0 วัน" หรือไม่ขยับไปตอนถัดไป (บทเรียนจากเวอร์ชันก่อนที่ตั้ง cache ไม่หมดอายุ)
- เวลาฉายแสดงเป็นเวลาญี่ปุ่นจนผู้ใช้ต้องแปลงเอง
- เข้าดูยาก — ต้องกดหลายชั้นกว่าจะเห็นว่าเรื่องไหนฉายเมื่อไหร่

## แหล่งข้อมูล

- **AniList GraphQL API** (`https://graphql.anilist.co`) เรียกจากเบราว์เซอร์ตรง ไม่ต้อง auth
- เลือก AniList แทน Jikan เพราะมี `nextAiringEpisode { episode, airingAt, timeUntilAiring }` และ `airingSchedules` ให้มาตรง ๆ ส่วน Jikan มีแค่ข้อความ broadcast ประจำสัปดาห์ (JST) ซึ่งต้องคำนวณเองและพลาดเมื่องดฉาย/เลื่อน
- กรอง `isAdult: false` ทุก query _(การตัดสินใจของผู้ออกแบบ)_
- AniList มี rate limit (ปกติ 90 req/นาที และเคยถูกลดเหลือ 30) — ต้องรับมือ 429 ด้วย retry ตาม header `Retry-After` และแสดงข้อความที่อ่านรู้เรื่องถ้ายังล้มเหลว

## หน้าเว็บ

### 1. หน้าแรก `/`

ประกอบด้วย section เรียงจากบนลงล่าง:

1. **ใกล้ฉาย** — ตอนที่จะฉายใน 24 ชั่วโมงข้างหน้า (จาก `airingSchedules` ช่วง now → now+24h) เรียงตามเวลาฉาย แสดงเวลาและ countdown
2. **มาแรง** — trending (`sort: TRENDING_DESC`, สถานะ `RELEASING`) ประมาณ 10–12 เรื่อง
3. **Top 10 ซีซันนี้** — 10 อันดับของซีซันปัจจุบัน
   _(การตัดสินใจของผู้ออกแบบ)_ เรียงตาม `averageScore` (เรื่องที่ยังไม่มีคะแนนไม่นับ); ถ้าต้นซีซันมีเรื่องที่มีคะแนนไม่ถึง 10 ให้เติมด้วยเรื่องที่ popularity สูงสุด และติดป้ายว่า "ยังไม่มีคะแนน"
4. **ซีซันหน้า** — เรื่องที่ประกาศแล้วของซีซันถัดไป เรียงตาม popularity ประมาณ 10–12 เรื่อง พร้อมลิงก์ "ดูทั้งหมด" ไปหน้าซีซันนั้น

ทุก section มีปุ่มบันทึกลงลิสต์บนการ์ด และกดการ์ดเข้าหน้ารายละเอียด

### 2. หน้ารวมซีซัน `/seasons`

แสดงซีซันเป็นตารางปี × ฤดู (Winter / Spring / Summer / Fall) ตั้งแต่ซีซันหน้าย้อนลงไป ไฮไลต์ซีซันปัจจุบัน
_(การตัดสินใจของผู้ออกแบบ)_ แสดงย้อนถึงปี 2000 บนหน้า; ปีที่เก่ากว่านั้นเข้าได้ผ่าน URL ตรง

### 3. หน้าซีซัน `/season/[year]/[season]` เช่น `/season/2026/fall`

- รายการอนิเมะทั้งหมดของซีซันนั้น
- _(การตัดสินใจของผู้ออกแบบ)_ แบ่งกลุ่มตาม format: TV, TV Short, Movie, OVA/ONA/Special
- เรียงได้: ใกล้ฉายที่สุด (ค่าเริ่มต้นสำหรับซีซันปัจจุบัน), popularity (ค่าเริ่มต้นสำหรับซีซันอื่น), คะแนน, ชื่อ
- แต่ละการ์ด: ปก, ชื่อ, สถานะการฉาย (ดูหัวข้อ "การแสดงสถานะ"), ปุ่มบันทึก
- ปุ่มไปซีซันก่อนหน้า/ถัดไป
- ต้องดึงครบทุกหน้า (pagination ของ AniList สูงสุด 50 ต่อหน้า) — ห้ามตัดที่ 50 เรื่อง

### 4. หน้ารายละเอียด `/anime/[id]`

- ชื่อ (romaji, English, native), ปก, banner
- เรื่องย่อ (ภาษาอังกฤษจาก AniList, ล้าง HTML ให้ถูกต้องรวมถึง entity อย่าง `&#x27;`, `&nbsp;`)
- แนว, สตูดิโอ, format, จำนวนตอน, ความยาวต่อตอน, source, สถานะ, วันเริ่ม/จบ
- คะแนนเฉลี่ย, popularity
- **ตอนถัดไป + countdown + วัน/เวลาฉายตามเวลาเครื่อง**
- trailer (ฝัง YouTube) ถ้ามี
- _(การตัดสินใจของผู้ออกแบบ)_ เรื่องที่เกี่ยวข้อง (prequel/sequel) เป็นลิงก์ไปหน้ารายละเอียด
- ปุ่มบันทึก/เอาออกจากลิสต์

### 5. หน้าลิสต์ของฉัน `/list`

- เรื่องที่บันทึกไว้ทั้งหมด พร้อมสถานะ/countdown แบบเดียวกับหน้าซีซัน
- _(การตัดสินใจของผู้ออกแบบ)_ เรียงค่าเริ่มต้นตามใกล้ฉายที่สุด; เรื่องที่จบแล้ว/ยังไม่เริ่มอยู่ท้าย
- เอาออกจากลิสต์ได้
- ลิสต์ว่าง → ข้อความชวนไปหน้าซีซัน

### Navigation

แถบเมนูทุกหน้า: หน้าแรก · ซีซัน (ไปซีซันปัจจุบัน) · ทุกซีซัน · ลิสต์ของฉัน

## การแสดงสถานะการฉาย (ใช้ร่วมทุกหน้า)

| สถานะ AniList                            | แสดง                                                |
| ---------------------------------------- | --------------------------------------------------- |
| `RELEASING` และมี `nextAiringEpisode`    | "EP x · อีก 2 วัน 4 ชม." + วัน/เวลา เช่น "ส. 22:30" |
| `RELEASING` แต่ไม่มี `nextAiringEpisode` | "กำลังฉาย" (ไม่มีกำหนดตอนถัดไป)                     |
| `NOT_YET_RELEASED`                       | "เริ่มฉาย <วันที่>" หรือ "ยังไม่ประกาศวัน"          |
| `FINISHED`                               | "จบแล้ว"                                            |
| อื่น ๆ (`HIATUS`, `CANCELLED`)           | ตามสถานะ                                            |

- เวลาทั้งหมดแสดงตาม **timezone ของเบราว์เซอร์** (ผู้ใช้อยู่ไทย)
- countdown อัปเดตเองทุก 1 นาทีโดยไม่ต้องรีโหลด
- เมื่อเวลาฉายผ่านไปแล้ว ให้ดึงข้อมูลเรื่องนั้นใหม่เพื่อเลื่อนไปตอนถัดไป ไม่ค้างที่ "อีก 0"
- ข้อมูลรอบฉายต้องรีเฟรชเองอย่างน้อยทุก 30–60 นาทีสำหรับแท็บที่เปิดค้าง

## ลิสต์ (storage)

- เก็บใน `localStorage` ของเบราว์เซอร์เครื่องเดียว
- เก็บ AniList ID พร้อม snapshot ขั้นต่ำ (ชื่อ, ปก) เพื่อให้หน้าลิสต์แสดงได้ทันทีก่อนข้อมูลสดมา; ข้อมูลรอบฉายดึงสดด้วย `id_in`
- _(การตัดสินใจของผู้ออกแบบ)_ ไม่มี export/import ในเฟสนี้
- _(การตัดสินใจของผู้ออกแบบ)_ เริ่มใหม่หมด ไม่ย้ายลิสต์จากเวอร์ชัน React เดิม (โค้ดเดิมไม่อยู่แล้ว) — เลือก storage key และ format ใหม่ได้อิสระ แต่ใส่ field `version` ไว้เผื่อเปลี่ยน format ภายหลัง
- ปุ่มบันทึกบนการ์ดและหน้ารายละเอียดต้องสะท้อนสถานะตรงกันทุกที่ทันที

## ภาษา UI

_(การตัดสินใจของผู้ออกแบบ)_ ป้าย/ข้อความ UI เป็นภาษาไทย; ชื่อเรื่องแสดง English ถ้ามี ไม่มีใช้ romaji; เรื่องย่อเป็นภาษาอังกฤษตามต้นทาง

_(การตัดสินใจของผู้ออกแบบ)_ ปีแสดงเป็น **ค.ศ.** ทุกที่ (เช่น "Fall 2026", "เริ่มฉาย 3 ต.ค. 2026") — ระวัง `th-TH` locale จะออกเป็น พ.ศ. โดยค่าเริ่มต้น ต้องใช้ `th-TH-u-ca-gregory` หรือเทียบเท่า

## Stack (ผู้ใช้ตัดสินใจแล้ว: ใช้ SvelteKit, ไม่ใช้ React/Next.js)

- **SvelteKit + Svelte 5 (runes) + TypeScript**
- **Bun** เป็น package manager / runner
- **GraphQL Codegen** สร้าง type จาก schema AniList
- **localStorage** สำหรับลิสต์
- **Vitest** สำหรับ logic (คำนวณ countdown/สถานะ, ฤดู/ปีปัจจุบันและถัดไป, การจัดการลิสต์, การล้าง HTML)
- _(การตัดสินใจของผู้ออกแบบ)_ แอปเป็น SPA (`ssr = false`) เพราะข้อมูลทั้งหมดดึงจากเบราว์เซอร์และลิสต์อยู่ใน localStorage
- **เรื่อง deploy ตัดออกจากเฟสนี้** (ผู้ใช้สั่ง) — รันบนเครื่องด้วย dev server เท่านั้น

## ผลตรวจกับ AniList จริง (2026-10-30)

ยิง query จริงแล้ว ทุก feature ทำได้ มีข้อควรระวังที่แผนต้องรองรับ:

- **CORS** เปิด (`access-control-allow-origin: *`) เรียกจากเบราว์เซอร์ได้ ไม่ต้องมี proxy
- **Rate limit ตอนนี้ 30 req/นาที** (header `x-ratelimit-limit: 30`, expose `X-RateLimit-Remaining/Reset` ให้อ่านได้) — หน้าแรกให้รวม 3 section (trending / top / ซีซันหน้า) เป็น query เดียวด้วย GraphQL alias (ทดสอบแล้วใช้ได้)
- **Pagination ของซีซัน**: `pageInfo.total`/`lastPage` เชื่อไม่ได้ (Fall 2026 ตอบ total 5000, lastPage 100 แต่ของจริงมี 102 เรื่องใน 3 หน้า) — ต้องวน `page` จน `hasNextPage = false`
- **ใกล้ฉาย 24 ชม.**: `airingSchedules(airingAt_greater, airingAt_lesser, sort: TIME)` ใช้ได้ (ตอนตรวจได้ 15 รายการ) แต่ filter `isAdult` ที่ระดับ query ไม่ได้ ต้องกรองฝั่ง client จาก `media.isAdult`
- **Top 10**: `sort: [SCORE_DESC, POPULARITY_DESC]` ใช้ได้; Fall 2026 มีคะแนนครบแล้ว แต่ยังต้องรองรับกรณีต้นซีซันตามที่ออกแบบไว้
- **เรียงตามใกล้ฉาย**: AniList ไม่มี sort แบบนี้ — เรียงฝั่ง client หลังดึงครบทุกหน้า
- **ลิสต์**: `Page { media(id_in: [...]) }` ใช้ได้ แต่ผลลัพธ์**ไม่เรียงตามลำดับ id ที่ส่งไป** และจำกัด 50 ต่อหน้า (ลิสต์เกิน 50 ต้อง paginate)
- **หน้ารายละเอียด**: field ครบ (title 3 ภาษา, cover, banner, description เป็น HTML มี `<br>`/`<i>`, genres, `studios(isMain: true)`, source, trailer `{id, site: "youtube"}`, relations) — relations มีทั้ง MANGA/NOVEL ต้องกรองเหลือ `type: ANIME`
- **วันที่ไม่ครบ**: `startDate` ของเรื่องที่ยังไม่ฉายมักมี `day: null` (หรือ month null) — แสดงแค่ส่วนที่มี เช่น "เริ่มฉาย ม.ค. 2027"
- **Introspection** เปิด ใช้กับ GraphQL Codegen ได้
- เวอร์ชัน package ตอนตรวจ: `@sveltejs/kit` 3.1.0, `svelte` 5.57.3, `graphql` 17.0.2 (โปรเจกต์ก่อนต้อง pin `graphql@^16` ให้เข้ากับ codegen — ให้ตรวจ peer range อีกครั้งตอนติดตั้ง)

## ทิ้งไว้ให้ผู้สร้างตัดสิน

- การจัดการ data fetching/cache (เช่น TanStack Query for Svelte หรือ store ที่เขียนเอง) ตราบใดที่ทำตามเงื่อนไขการรีเฟรชและ countdown ด้านบน
- GraphQL client (fetch เปล่า หรือ library เล็ก ๆ)
- โครงสร้างโฟลเดอร์, ชื่อ component
- การคำนวณ "ซีซันปัจจุบัน" (ขอบเขตเดือนของแต่ละฤดูตามแบบ AniList)
- หน้าตา loading / error state (ให้ใช้งานได้และอ่านรู้เรื่องพอ)

## หมายเหตุ

- โฟลเดอร์โปรเจกต์ตอนนี้ว่าง และยังไม่ใช่ git repo — ต้อง `git init` ก่อนเริ่ม
- เวอร์ชันก่อน (React) เคยมีปัญหาที่บันทึกไว้: cache ไม่หมดอายุทำให้ countdown ค้าง, `perPage: 50` ตัดข้อมูลโดยไม่ paginate, stripHtml ไม่ครอบคลุม entity — เอกสารนี้กำหนดไว้แล้วว่าต้องไม่เกิดซ้ำ

## แก้ไขหลังส่งมอบ (2026-10-30, รอบ design gate)

- **หน้าแรก render ฝั่ง server (SSR)** เฉพาะ `/` (`src/routes/+page.ts`, `ssr = true`): ดึง Home + ตารางฉาย 24 ชม. ตอน render แล้วส่งเป็น `initialData` ให้ TanStack Query — จอแรกมีปกและตารางทันทีโดยไม่ต้องรอ JS; ตอน hydrate SvelteKit ตอบ fetch จาก response ที่ฝังในหน้า จึงไม่ยิง AniList ซ้ำ หน้าอื่นยังเป็น SPA (`ssr = false` ที่ layout)
- ถ้า AniList ล่ม/โดน rate limit ตอน render (ไม่ retry ฝั่ง server) หน้าแรกจะกลับไปโหลดฝั่ง client ตามเดิม
- ฝั่ง server ใช้ QueryClient ใหม่ต่อ request และปิด query (`enabled: browser`) เพื่อไม่ให้ข้อมูลรั่วข้าม request
- ผลข้างเคียง: การ deploy ในอนาคตต้องเป็นแบบมี server (หรือ adapter ที่รองรับ SSR) ไม่ใช่ static ล้วน
