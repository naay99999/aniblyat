# aniblyat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A personal SvelteKit SPA on AniList that shows what's airing (with live countdowns), season pages, a sectioned home page, anime detail, and a localStorage watchlist.

**Architecture:** Client-only SvelteKit app (`ssr = false`). Pure logic (seasons, airing status, formatting, top-10 selection, pagination, storage) lives in small tested TS modules under `src/lib/`. Data access goes through one AniList client with 429 retry; queries are cached with TanStack Query (Svelte) and refreshed on a timer and whenever a shown episode's `airingAt` passes. UI is functional and unstyled beyond basic responsive layout — visual design is a later phase.

**Tech Stack:** Bun, SvelteKit 3 + Svelte 5 (runes) + TypeScript, `@tanstack/svelte-query`, GraphQL Codegen (client preset), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-30-aniblyat-design.md` (includes the "ผลตรวจกับ AniList จริง" section — read it).

## Global Constraints

- No React, no Next.js.
- No deploy work in this phase; `bun run dev` locally is the target. `bun run build` must still succeed.
- Endpoint `https://graphql.anilist.co`, no auth. Every `Media` query passes `isAdult: false`; `airingSchedules` results are filtered client-side on `media.isAdult`.
- Rate limit is 30 req/min: home page sections trending/top/next-season are ONE aliased query.
- Paginate by `pageInfo.hasNextPage` only — never trust `pageInfo.total`/`lastPage`. `perPage: 50`.
- All times shown in the browser's timezone. Years always Gregorian (use locale `th-TH-u-ca-gregory`).
- UI copy in Thai. Title = `title.english ?? title.romaji`.
- Airing data refreshes at least every 30 min (`staleTime` and `refetchInterval` = 30 min) and a query is invalidated as soon as any `nextAiringEpisode.airingAt` it returned is ≤ now. Countdowns re-render every 60 s.
- Watchlist key `aniblyat:list`, value `{ version: 1, items: WatchItem[] }`.
- `graphql`: check `@graphql-codegen/client-preset`'s peer range at install; if it does not include 17, pin `graphql@^16`.

## Review Focus

1. A tab left open past an episode's air time: the badge must move to the next episode without reload, not sit at "อีก 0 นาที". → Task 5 test `invalidates when airingAt passes`.
2. localStorage throwing (private mode) or holding junk JSON: the app must load with an empty list, not crash. → Task 6 tests.
3. Bad URLs (`/season/2026/autumn`, `/season/abc/fall`, `/anime/xyz`, `/anime/999999999`): show a Thai "ไม่พบ" page, not a blank screen or uncaught error. → Task 3 test `parseSeasonParams rejects`, Task 2 test for GraphQL 404, Task 10 step.
4. AniList returns 429: wait `Retry-After` seconds and retry (max 2 retries), then show a readable error with a retry button. → Task 2 tests.
5. Season with >100 entries and watchlist with >50 items: every item shown. → Task 2 `fetchAllPages` test, Task 5 `getMediaByIds` chunking test.
